# LAN 内機器一覧（Fing 風）機能の構想（案）

作成：2026-10-17。2026-10-17 のユーザー要望「できれば Fing みたいな機能『LAN 内の機器一覧取得』も入れたい」に対する構想。**未実装・提案段階。**

## 1. ねらい

単体のネットワークスキャナーではなく、**機器台帳と突き合わせる**ことに価値を置く。

- 「LAN にいるのに台帳に無い機器」を見つけて、そのまま台帳登録（IP・ホスト名・メーカー・型番・管理画面URLを下書きに反映）。
- 「台帳にあるのに応答が無い機器」「IP が変わった機器（DHCP）」を知らせる。
- SR5900P などプリンターも同じ一覧から見つけ、ラベル印刷へつなぐ。

## 2. Android（11〜16, targetSdk 35）での技術的な制約

| 制約 | 影響 | 対策 |
| --- | --- | --- |
| `/proc/net/arp` は Android 10 以降アプリから読めない。`ip neigh` も targetSdk 30 以降は不可 | **他機器の MAC アドレスは原則取得できない**（Fing のスマホ版も同じ制約） | MAC は ①NetBIOS 応答、②SNMP、③mDNS/UPnP の付帯情報、④台帳の既存値・銘板OCR から補完。取得できない場合は「不明」と明示 |
| 生ソケット（ICMP）は使えない | 本物の ping スイープ不可 | `InetAddress.isReachable`（実体は TCP echo）＋主要ポートへの TCP 接続試行＋`/system/bin/ping` の併用 |
| `usesCleartextTraffic="false"` | HttpURLConnection で `http://` 管理画面の確認ができない | 識別用の HTTP 取得は `Socket` で直接 HEAD/GET（ネットワークセキュリティ設定の対象外）。台帳本体の通信方針は変えない |
| マルチキャスト受信には MulticastLock が必要 | mDNS/SSDP が拾えない | 既存の `CHANGE_WIFI_MULTICAST_STATE` 権限で取得（追加権限なし） |
| SSID 表示には位置情報権限が必要 | ネットワーク名が出ない | 位置情報は**要求しない**。ゲートウェイ IP とサブネットでネットワークを識別。SSID は任意設定 |
| 将来の Android で「ローカルネットワークアクセス」が実行時権限化される見込み | 新しい targetSdk で動かなくなる恐れ | 権限要求の導線を最初から用意し、拒否時は手動 IP 入力のみに縮退。targetSdk を上げる時に再確認 |

## 3. 検出・識別の方法（端末内処理のみ、外部サーバーへ送らない）

| 手段 | 得られるもの | 備考 |
| --- | --- | --- |
| サブネット算出 | 自端末 IP・プレフィックス長・ゲートウェイ | `ConnectivityManager.getLinkProperties()`。既定は /24、最大 /22（1022 台）に制限 |
| 生存確認スイープ | 応答した IP | 同時 64 並列・タイムアウト 300〜500ms。/24 で 10〜20 秒目安 |
| TCP 接続試行（少数の固定ポート） | 開いているサービス | 22, 80, 443, 445, 515, 554, 631, 3389, 5000, 8080, 8443, 9100 程度に限定。範囲指定のポートスキャンはしない |
| 逆引き DNS（PTR） | ホスト名 | ルーターの DNS が答える場合 |
| mDNS / DNS-SD | ホスト名、サービス種別（`_ipp._tcp` `_http._tcp` `_airplay._tcp` `_googlecast._tcp` `_smb._tcp` 等）、TXT（機種名・UUID 等） | `_services._dns-sd._udp.local` で列挙 |
| SSDP / UPnP | friendlyName、manufacturer、modelName、modelNumber、serialNumber、**presentationURL** | presentationURL はそのまま「管理画面URL」候補になる |
| NetBIOS（UDP 137 NBSTAT） | Windows / NAS のコンピューター名と **MAC** | MAC が取れる貴重な手段 |
| SNMP v2c（`public`、読み取りのみ・任意） | sysName、sysDescr、ifPhysAddress（MAC） | プリンター・ネットワーク機器で有効。既定オフ |
| HTTP タイトル／Server ヘッダー | 管理画面のタイトル（例「EPSON TM-T88VI」） | 認証情報は**送らない**。自己署名証明書は識別目的に限り許容 |
| OUI ベンダー表 | MAC → メーカー名 | IEEE 公開リストを APK に同梱（圧縮で数百 KB〜1MB）。オフラインで引く |

識別結果は「候補」として扱い、Gemini 候補と同様に**ユーザーが確認して台帳へ反映**する（自動上書きしない）。

## 4. 画面と台帳連携

- 一覧画面に「LAN」タブ（または上部ボタン）を追加。「スキャン開始」→ 進捗表示 → 結果一覧。
- 各行：種別アイコン、名前（台帳名 > mDNS/NetBIOS 名 > UPnP 名 > IP）、IP、MAC（不明可）、メーカー/型番候補、検出手段のバッジ、台帳状態。
- 台帳状態の判定（優先順）：MAC 一致 → ホスト名一致 → IP 一致。
  - **登録済み**（緑）／**未登録**（黄、「台帳に追加」ボタン）／**IP 変更の可能性**（「台帳の IP を更新」確認）／**台帳にあるが応答なし**（灰、一覧の末尾）。
- 「台帳に追加」→ 既存の新規登録画面を下書き付きで開く（IP・MAC・メーカー・型番・URL）。写真撮影・ラベル印刷は既存フローのまま。
- 詳細：開いているサービス一覧、「管理画面を開く」（外部ブラウザ）、「この機器でラベルを作る」。
- スキャン結果の保存：最終確認日時を各台帳レコードの JSON に `lastSeen` / `lastIp` として追加（**既存スキーマのまま**。JSON キー追加なので DB バージョン変更不要）。スナップショットは暗号化ファイル `files/lan-scan` に直近 1 回分のみ。`.eqbk` バックアップには含めない（端末・ネットワーク固有のため）。

## 5. 安全・マナー

- スキャン対象は**今つながっているネットワークのみ**。初回に「自分が管理する／許可されたネットワークでのみ使用してください」と表示（社内ネットワークではスキャンが規程違反になる場合がある）。
- 固定の少数ポートのみ・同時接続数とレート制限・手動開始のみ（バックグラウンド定期スキャンは初期版ではしない）。
- ログイン試行・脆弱性診断・既定パスワード確認などは**行わない**。
- 結果は端末内のみ。Gemini には送らない（ユーザーが選んだ写真の認識だけという既存方針を維持）。

## 6. 実装の構成（案）

| クラス | 役割 | テスト |
| --- | --- | --- |
| `LanScanner` | サブネット算出、並列スイープ、キャンセル、進捗通知（ExecutorService） | 擬似ホストでの単体テスト |
| `Mdns` / `Ssdp` / `NetBios` / `SnmpLite` | 送信パケット生成と応答の**純粋 Java パーサー** | 実機器から採取した応答バイト列をフィクスチャにして JUnit |
| `HttpProbe` | Socket での HEAD/GET、`<title>`・Server 抽出 | 同上 |
| `Oui` | OUI 表の読み込みと検索 | JUnit |
| `LanMatch` | スキャン結果と台帳の突き合わせ（MAC→ホスト名→IP） | JUnit（台帳状態 4 種） |
| `LanUi` | 一覧・詳細・台帳追加への連携 | Robolectric |

開発用に、PC/Mac の Python 3.12 で動く**ダミー機器スクリプト**（SSDP と mDNS に応答し、HTTP で管理画面風ページを返す）を `tools/lan-fake-device.py` として用意し、実機での動作確認に使う。

## 8. ユーザーに確認したいこと

1. 主な利用場所（自宅 LAN／職場 LAN）。職場ならスキャンの許可を得られるか。
2. MAC が取れない機器が多いことは許容できるか（台帳側の MAC は銘板 OCR で補う運用）。
3. SNMP（`public` コミュニティ読み取り）を任意機能として入れてよいか。
4. まず L1〜L2 で 1.3.0 を出す範囲でよいか。
